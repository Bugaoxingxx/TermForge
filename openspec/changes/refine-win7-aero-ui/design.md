## Context

TermForge 当前由 WPF 主窗口、MMC 三栏外壳、自定义 MDI 容器和终端文档组成。`AeroTheme.xaml` 已提供渐变、标题按钮和工具栏样式，但应用没有显式加载 WPF 的 Windows 7-era Aero 控件主题，主窗口也没有自定义非客户区；因此主标题栏随宿主系统变化，而 Menu、TextBox、ScrollBar 等标准控件与局部自绘样式可能来自不同设计年代。MDI 子窗口还在控件内部重复维护一组局部画刷和按钮模板。

本变更跨越 `AgentTerminal.App` 与 `AgentTerminal.Docking`，但不改变 ViewModel 命令、会话生命周期、终端协议或 MDI 几何行为。当前 `add-terminal-rendering` 正在用 `TerminalControl` 替换调试 TextBox；本变更必须避免在即将被替换的诊断视图上重复投入，并在该接入完成后收口终端宿主边界。

## Goals / Non-Goals

**Goals:**

- 在 Windows 10/11 上提供稳定、统一且容易被识别为 Windows 7 Aero/MMC 的桌面外观。
- 让主窗口、标准控件、工作台面板和 MDI 子窗口共享一套颜色、度量、字体、状态和图标系统。
- 在自定义主窗框下保留 Windows 用户预期的拖动、缩放、最大化、系统菜单、Snap 和键盘行为。
- 在 100%～200% DPI、高对比度和键盘操作下维持可读、可见、可操作的界面。
- 将视觉验收变成可重复的检查，而不是只依赖单张概念图。

**Non-Goals:**

- 不逐像素复刻 Windows 7 的 DWM 合成器，也不承诺不同 Windows 版本上完全相同的字体栅格化结果。
- 不改变终端 VT 解析、字符缓冲、渲染、输入映射或 ConPTY 会话语义。
- 不在本变更中实现多主题热切换、外部停靠、标签模式或布局持久化。
- 不重新设计品牌标志；仅把现有标志加工成适合窗口、任务栏和高 DPI 的资源格式。
- 不高成本重绘即将退居诊断用途的 `TerminalDebugView`。

## Decisions

### 1. 以 WPF 内置 Aero 主题为标准控件基线

`App.xaml` 将先合并 `/PresentationFramework.Aero;component/themes/Aero.NormalColor.xaml`，随后合并 TermForge 主题覆盖。合并顺序保证 Button、MenuItem、ScrollBar、TextBox、TreeView 等未定制控件首先获得同一时代的默认模板，同时允许产品特有样式覆盖颜色和度量。

替代方案是继续完全手写所有控件模板。该方案会显著增加 ComboBox、ScrollBar、焦点、禁用状态和高对比度遗漏风险，因此不采用。若目标 .NET 运行时没有自动包含主题程序集，则增加框架主题程序集引用，但不引入第三方 UI 框架。

### 2. 主题资源按职责拆分并保持库边界

应用主题拆为颜色、度量/字体、标准控件和主窗框资源字典。MDI 专属样式放在 `AgentTerminal.Docking/Themes/AeroDockingTheme.xaml`，由应用显式合并；`MdiChildWindow` 只通过资源键消费样式，不再内联重复渐变和按钮模板。

资源键以语义命名，例如活动窗口标题、非活动窗口标题、外壳分隔线和危险命令，而不是以某一个页面命名。动态状态使用 `DynamicResource`，固定几何和度量使用 `StaticResource`。这样既避免 Docking 库反向依赖 App，也为未来主题替换保留边界。

### 3. 使用 WindowChrome 保留系统行为，自绘 Win7 外观

主窗口采用 `WindowChrome` 与自定义 Window 模板，保持 `AllowsTransparency=false`，避免透明窗口导致的软件渲染、Snap 异常和阴影兼容问题。视觉层使用 XAML 渐变、双线边框和克制的高光模拟 Aero；不依赖旧版 DWM 模糊可用性。

标题区域提供应用图标、标题和最小化/最大化/关闭按钮。CaptionHeight 和 ResizeBorderThickness 定义系统交互区域；交互控件标记为可在 Chrome 中命中。实现必须保留双击标题最大化、右键/Alt+Space 系统菜单、最小化、还原、Snap，以及最大化后不覆盖任务栏的工作区约束。

替代方案是保留系统标题栏。它的行为风险最低，但在 Windows 11 上会持续产生最明显的时代混搭，因此不采用。直接请求 DWM Aero Glass 仅作为历史系统上的可选增强也不采用，因为无法成为跨版本可靠基线。

### 4. 视觉真实性来自层级与度量，而不是增加特效

标准 UI 字体采用 Segoe UI，并为简体中文回退到 Microsoft YaHei UI；常规界面字号使用 12 DIP（约 9pt），辅助信息不得低于 11 DIP。布局使用 5/7/11 DIP 的标签、相关项和分组间距节奏，常规命令按钮高度统一为 23～24 DIP。

玻璃与强高光仅用于主窗框和 MDI 标题栏。工作台面板采用浅色平面背景、细分隔线和少量凹陷输入框；移除属性面板的现代卡片堆叠、非必要圆角和重复阴影。阴影用于建立活动窗口层级，非活动窗口显著减弱。工作区采用安静的蓝灰底色或极弱纹理，终端视口保持不透明深色。

### 5. 工具栏是高频命令入口，不复制完整菜单

菜单继续承载完整命令目录和访问键。工具栏只保留新建终端、停止会话、窗口排列入口和必要的清空操作；层叠、水平平铺、垂直平铺合并为一个排列菜单或分裂按钮。工具栏按钮常态弱化边框，仅在 Hover、Pressed、Focus 和 Checked 等状态显示明确反馈。

界面文本统一为中文，不再在面板标题中附加 `MMC`、`Sessions`、`Properties`、`Diagnostics` 等重复英文。状态栏只显示动态状态、会话/活动文档和必要指示，不放固定品牌标语。

### 6. 图标使用 WPF 原生可缩放资源与多尺寸应用图标

控件中的 Emoji/Unicode 符号替换为像素对齐的 `DrawingImage`/`Path` 或针对 16×16 尺寸优化的透明位图。窗口按钮使用几何路径，以避免不同字体和语言环境产生不同字形。应用图标打包为含 16、24、32、48、256px 图像的 `.ico`，用于窗口、任务栏和 Alt+Tab。

不引入 SVG 渲染库；现有 SVG 可作为设计源，但运行时资源转换为 WPF 原生几何、PNG 或 ICO。

### 7. 终端外壳与终端内容分层

`TerminalControl` 的字符网格、颜色和焦点行为由 `add-terminal-rendering` 负责。当前变更只定义其外部窗口边框、标题栏和可选会话命令区域，不向终端视口叠加透明度、圆角、阴影或玻璃。最终接入任务在 `TerminalControl` 成为主文档视图后执行；此前只做能被复用的主题基础设施。

### 8. 视觉验收采用固定矩阵

人工截图基线至少覆盖 100%、125%、150%、200% DPI，以及 1024×768 和常见宽屏尺寸。自动化测试继续验证标题栏命令、拖动、最大化、缩放、快捷键和 AutomationId，不使用脆弱的全屏逐像素断言。视觉检查聚焦裁切、模糊边线、图标缩放、状态区分和跨区域一致性。

## Risks / Trade-offs

- **[自定义 Chrome 容易破坏系统窗口行为]** → 先建立窗口行为自动化测试，再替换视觉模板；保持非透明顶层窗口，并逐项验证系统菜单、Snap、最大化边界和 DPI。
- **[内置 Aero 主题在未来 .NET 版本中的细节可能变化]** → 把它作为标准控件基线而不是唯一视觉来源，对关键控件保留产品级覆盖和截图基线。
- **[共享主题拆分可能出现资源加载顺序错误]** → 在 App 中集中声明固定合并顺序，并增加启动烟雾测试确保关键资源可解析。
- **[大量 DropShadowEffect 影响 WPF 渲染性能]** → 仅主窗框和活动 MDI 窗口使用阴影，禁止在终端字符网格及重复列表项中使用效果。
- **[高对比度模式与固定 Aero 色冲突]** → 为高对比度提供系统色资源分支，重要状态同时使用文字、图标或边框表达。
- **[与终端渲染变更同时修改文档宿主产生冲突]** → 先完成主题和窗框，MDI 内容宿主最终收口任务显式依赖 `add-terminal-rendering` 的接入任务。
- **[经典外观可能牺牲部分现代审美]** → 将目标限定为专业 Win7/MMC 工作台，减少装饰而不削弱可访问性和高 DPI 支持。

## Migration Plan

1. 建立窗口行为、资源加载和当前关键 AutomationId 的回归基线。
2. 引入内置 Aero 基线及分层资源字典，但暂不改变布局与命令。
3. 替换主窗框并通过窗口行为测试；若失败，可单独回退 Window 样式而保留其余主题资源。
4. 逐区迁移菜单/工具栏、导航/属性/状态栏和图标，保持原绑定与 AutomationId。
5. 将 MDI 局部资源迁到 Docking 主题，再替换子窗口模板与最小化托盘。
6. 等 `TerminalControl` 接入后完成终端宿主边界和焦点验收。
7. 在 DPI/高对比度矩阵完成视觉验收后更新现有设计文档，移除“跨系统 100% 像素级还原”等不可验证承诺。

## Open Questions

- 工作区背景最终采用纯蓝灰渐变还是极弱纹理，应在两张真实运行截图中比较后确定；默认先使用无纹理方案以降低视觉噪声。
- 工具栏“窗口排列”使用标准 MenuButton 还是自定义 SplitButton，取决于内置 Aero 模板下哪一种能以更少自定义保持键盘可访问性。
- 高对比度切换是否要求运行时即时更新，需在实现阶段确认 WPF 系统参数通知行为；最低要求是重新打开窗口后正确应用。
