# TermForge PRD：MMC 风格 MDI 工作台与 PowerShell 会话

版本：0.3 | 日期：2026-09-05 | 状态：待实现

配套任务：[开发 TODO](TODO-Phase1-ConPTY.md)。背景：[总体开发计划](../Windows原生Agent_Terminal开发计划.md)、[架构设计](ARCHITECTURE.md)。

本文统一管理底层会话与 MDI 工作台：第 1～9 节定义首轮会话闭环，第 10～14 节定义多文档交互、验收和后续交付。FR/AC 为会话需求与验收编号，MDI 为工作台需求与验收编号。

## 1. 背景与当前基础

TermForge 的产品目标是 Windows MMC 风格的 MDI 多文档 Shell 与 Agent CLI 工作台，具体交互见本文第 10～14 节。本轮交付单个 PowerShell 会话的底层闭环，并将调试视图承载在工作台外壳的单个文档中，为后续多文档、字符缓冲、VT 解析和原生渲染提供基础。

截至本文编写时，仓库已有多项目结构、`ITerminalSession`、`ShellProfile`、会话状态枚举和部分模型测试。ConPTY 目录仅有常量；VT 解析器为空实现；TerminalControl 仅绘制背景；主窗口为空；TerminalBuffer 尚未存储字符网格。README 中的产品特性描述不代表这些能力已经实现。

## 2. 用户与核心场景

目标用户是开发 TermForge 的工程师和进行本地验证的测试人员。

核心流程：打开调试窗口 → 启动 PowerShell → 输入并发送命令 → 观察输出 → 中断或正常退出 → 确认会话及子进程已清理。

本轮价值是证明 ConPTY、输入输出和生命周期能协同工作。调试输出区不承担完整终端模拟器的职责。

## 3. 首轮会话闭环范围

### 本轮交付

- 一个基于 ConPTY 的 PowerShell 7 会话；默认使用 `pwsh.exe -NoLogo`。
- 启动、命令发送、输出读取、中断、调整行列数、停止和退出状态反馈。
- 支持可执行文件、参数、工作目录和会话环境变量的启动配置。
- MMC 风格 WPF 工作台外壳中的单文档调试视图，以及独立于 UI 的会话集成测试。
- Job Object 进程树管理、启动失败回收和关闭时资源清理。
- 中文解码、高频输出、反复启停及宿主异常退出验证。

### 后续阶段

- 字符网格、完整 VT/ANSI 解析、颜色、光标和 Alternate Screen。
- 终端原位编辑、方向键、Tab 补全、Backspace、完整快捷键及鼠标选区体验。
- CMD、Windows PowerShell、WSL 的正式兼容性验收。
- 完整 MDI 多文档操作与多会话接入（见本文第 10～14 节）、多标签、Docking、Agent Profile、Workspace、安装包和发布。

本轮是总体计划 Phase 1 的底层验证里程碑；“可在自研窗口中像现代终端一样完整交互”的验收仍需后续 Buffer、VT、Renderer 和 Input 工作，不能因本轮通过而标为完成。

## 4. 功能需求

| 编号 | 需求 | 行为与验收要求 |
| --- | --- | --- |
| FR-01 | 创建和启动会话 | 实现现有 `ITerminalSession`；启动成功进入 Running。找不到 pwsh 或工作目录无效时进入 Failed，界面显示可操作的错误原因；不静默切换其他 Shell。 |
| FR-02 | 启动配置 | 使用 ShellProfile 的路径、参数、工作目录和环境变量；自定义变量覆盖会话继承的同名变量，不修改宿主环境。支持路径包含空格。 |
| FR-03 | 双向通信 | Running 时可发送文本和字节；“发送命令”追加回车。输出通过现有事件交付，保持每条输出流的顺序；文本采用跨读取块保留状态的 UTF-8 解码，避免中文因分块而损坏。 |
| FR-04 | 中断 | 提供显式“中断”操作，通过输入流发送 Ctrl+C 对应字节；对受控前台长命令验收，中断后同一会话仍可执行下一条命令。 |
| FR-05 | 调整尺寸 | 提供列数和行数输入及应用按钮；合法值调用底层调整 API，成功后更新 Dimensions；无效值明确拒绝，保留原尺寸。不要求本轮自动按字体和窗口大小计算网格。 |
| FR-06 | 生命周期 | 反映 Created、Starting、Running、Stopping、Exited、Failed；真实进程退出时记录退出码，ProcessExited 每个已创建进程至多触发一次。正常退出和用户停止不作为故障。 |
| FR-07 | 清理与恢复 | 停止、窗口关闭、启动中失败和宿主异常退出后，不残留本会话 Shell 及受控子进程。重复停止和释放安全；结束后可新建会话重新启动。 |
| FR-08 | 工作台内调试文档 | 外壳包含菜单、工具栏、左侧导航、中央文档区和状态栏；单个调试文档展示配置、状态、输出、错误和退出码，提供启动、发送、中断、调整尺寸、停止、清空显示。按钮按状态启用；清空显示不向 Shell 发送清屏命令。完整多文档按本文 MDI-01 至 MDI-08 验收。 |
| FR-09 | 诊断 | 记录会话 ID、状态变化、进程 ID、关键操作、错误码和耗时；默认不将完整命令、终端输出或环境变量值写入持久化日志。 |

### 生命周期约定

- 正常路径：Created → Starting → Running → Exited。
- 主动停止：Starting/Running → Stopping → Exited；启动期间取消也必须回收已分配资源。
- 启动或运行发生基础设施错误：Starting/Running → Failed，并完成清理；用户再次启动时创建新实例。
- Created 状态停止可直接进入 Exited；对 Exited/Failed 的停止与释放不再产生状态抖动。
- 同一实例不重复启动；并发启动被拒绝。非 Running 状态的写入与尺寸调整返回明确错误，不排队到下一会话执行。
- 退出码仅在确实取得进程退出结果后赋值；启动前失败不伪造退出码或进程退出事件。

## 5. 调试交互与输出策略

主窗口采用 MMC 风格工作台布局，菜单和工具栏置顶、导航树居左、文档工作区居中、状态栏置底。调试视图位于文档内部：顶部显示启动配置和状态，中部为只读输出区，底部为命令输入与操作按钮。首次进入 Created，只有启动和配置操作可用；启动成功后启用发送、中断、调整尺寸和停止。退出后保留输出与退出信息，允许重新启动。该文档以后可替换为完整终端视图，外壳无需重建。

输出区明确标识为“调试输出”。允许将 ESC 等控制字符显示为可辨识的转义形式，不把原始 VT 字节流误称为已经正确渲染的终端画面。输入框采用普通文本编辑行为。

读取与 UI 更新解耦，以约 16ms 的批次刷新为初始实现策略。显示缓冲和待刷新队列都必须有界；建议分别限制为最近 1 MiB 文本和 1 MiB 待刷新数据，超限时丢弃最旧显示数据并显示截断提示。截断仅影响调试显示，底层无 UI 的验证消费者仍应能校验完整输出。事件消费者的线程、缓慢消费与背压约定需在实现中明确。

## 6. 工程边界

- 复用 .NET 8、WPF 和现有分层，不在本轮变更运行时或发布模式。
- Core 保留会话抽象与模型；Terminal 实现 ConPTY 会话与读写；Infrastructure 提供 Job Object 等系统资源封装；App 通过 ViewModel 连接调试交互。若新增项目引用，应保持无循环依赖。
- 创建进程、加入 Job Object 与开始执行之间不得留下未受管理子进程的窗口；Job 绑定失败时停止启动并回收。
- 所有原生句柄明确归属；退出和停止时保持输出排空、管道关闭与 ConPTY 关闭的协调，避免等待读取或关闭永久挂起。
- 取消和失败也走完整清理路径。UI 不逐字符派发更新，不等待阻塞式 I/O。

以下数值是本轮拟定验收门槛，不是已有性能结果。验收报告需记录 Windows、.NET、PowerShell 版本和机器配置；集成测试使用 `-NoLogo -NoProfile` 降低个人配置干扰，另人工验证默认参数。

| 编号 | 关联需求 | 验证场景与通过标准 |
| --- | --- | --- |
| AC-01 | FR-01、02、03、08 | 启动 PowerShell 并执行含唯一标识的简单命令，10 秒内收到实际执行结果；验证指定工作目录及会话变量生效，宿主变量不变。不得仅匹配输入回显作为成功依据。 |
| AC-02 | FR-03 | 输出中文、ASCII、Emoji 混合文本；测试人为拆开的 UTF-8 多字节边界，解码后内容完整且无新增替换字符。此项只验证传输与解码。 |
| AC-03 | FR-04 | 执行受控长命令，发送中断后 5 秒内可执行下一条唯一标识命令；会话保持可用。 |
| AC-04 | FR-05 | 连续应用 80×24、120×30、160×50，Shell 侧观测尺寸与请求一致；无效尺寸被拒绝，原会话仍可用。 |
| AC-05 | FR-06、07 | 分别执行 exit 0、exit 7，退出码正确且事件不重复；停止后 5 秒内受控 Shell 和子进程消失；重复释放不报错。 |
| AC-06 | FR-01、06、07、09 | 无效路径、无效目录、模拟 Job 绑定失败、启动中取消均有明确结果；无残留进程和未释放的已分配句柄，可新建实例再启动。 |
| AC-07 | FR-03、08 | 生成至少 100,000 行带序号输出和结束标识，无 UI 消费者在 60 秒内校验序号完整且有序；连接调试 UI 后仍能停止，操作反馈不超过 1 秒，显示与队列不超过设定上限并正确提示截断。 |
| AC-08 | FR-06、07 | 预热后连续创建、启动、停止 100 次；每次进程均结束。记录清理后的宿主句柄数，末 10 次中位数不超过首 10 次中位数加 10，异常增长需定位并重测。 |
| AC-09 | FR-07 | 在独立测试宿主中启动 Shell 及受控子进程，外部强制结束该宿主，5 秒内进程树被清理；只终止本测试创建并记录的进程。 |

## 10. MDI 产品目标

实现用户指定的 Windows MMC 风格 MDI 多文档界面：一个主窗口容纳多个可独立操作的终端文档，以菜单栏、工具栏、导航树、文档工作区和状态栏构成桌面工作台。

本项目将 MDI 具体定义为：文档子窗口可在主窗口工作区内移动、调整大小、重叠、层叠、平铺、最小化、最大化、还原和关闭。标签切换可以作为补充，但仅有标签页不能满足本需求。这里定义的是 TermForge 的目标交互，不要求复刻 MMC 的内部实现或所有管理功能。

## 11. MDI 界面布局

| 区域 | 内容与行为 |
| --- | --- |
| 顶部菜单栏 | 文件、视图、窗口、帮助；文件提供新建终端、关闭当前文档和退出；窗口提供文档列表、层叠、水平平铺、垂直平铺和全部还原。 |
| 工具栏 | 新建终端、停止当前会话、切换布局；操作随活动文档与会话状态启用。 |
| 左侧导航树 | 工作区、项目和会话的层级入口；初期可仅显示本地会话。选择已有会话激活对应文档，不重复启动进程。 |
| 中央 MDI 工作区 | 多个带标题和窗口控制按钮的文档子窗口；每个终端文档拥有独立会话、输出、状态和输入焦点。 |
| 右侧属性/操作区 | 显示当前文档的 Shell、目录和状态，允许隐藏。 |
| 底部日志区与状态栏 | 日志区可隐藏；状态栏显示活动文档和会话状态。 |

视觉采用紧凑菜单与工具栏、清晰分隔线、树形导航和常规窗口控制。管理区域默认浅色，终端区域可使用深色；颜色不得作为唯一的活动或错误标识。实现前先提供可运行的布局原型核对空间比例与操作方式。

## 12. MDI 功能需求与验收

| 编号 | 需求 | 通过标准 |
| --- | --- | --- |
| MDI-01 | 工作台外壳 | 主窗口包含菜单、工具栏、导航树、中央工作区和状态栏；属性及日志区可以显示和隐藏。 |
| MDI-02 | 多文档管理 | 能新建至少 3 个独立终端文档；标题显示名称和状态；切换活动文档后菜单、属性及输入目标同步变化。 |
| MDI-03 | 子窗口操作 | 3 个文档可在工作区内拖动、缩放、重叠；支持层叠、水平平铺（上下排列）、垂直平铺（左右排列）、最小化、最大化、还原和关闭。最大化后仍可切换其他文档；最小化后可从窗口菜单恢复。 |
| MDI-04 | 输入与会话隔离 | 向 A 文档发送唯一标识命令，仅 A 会话执行；激活 B 后输入进入 B；关闭 A 不终止 B、C。 |
| MDI-05 | 布局不影响进程 | 对运行中的文档执行移动、缩放、层叠、平铺、最小化和最大化后，会话 ID 与进程 ID 不变，运行中命令继续执行。尺寸变化在完整终端控件接入后传给对应 ConPTY。 |
| MDI-06 | 导航与键盘 | 导航树与窗口菜单可定位任一打开文档；Ctrl+Tab 切换文档，Ctrl+F4 关闭当前文档；输入焦点与活动文档一致，不拦截无关终端按键。 |
| MDI-07 | 工作区恢复 | 保存文档启动配置、窗口位置和尺寸、窗口状态、活动文档及辅助面板可见性；重启后恢复布局，并显式启动新会话，不能声称恢复旧进程或运行中命令。屏幕或主窗口变小时子窗口仍可找回。 |
| MDI-08 | 主窗口与资源清理 | 关闭文档清理其会话，退出主窗口清理所有会话；某一会话失败不使其他文档不可用。 |

窗口数量超过 3 个时仍需支持文档列表定位；20～50 会话压力验收沿用后续生命周期阶段，不以 3 文档测试替代。

## 13. MDI 架构与技术选型约束

- 保留 WPF、ConPTY 和原生终端渲染路线。文档容器承载自有终端视图，不嵌入外部 Shell GUI 窗口。
- 文档管理负责创建、激活、关闭和布局；会话管理负责进程与 I/O。视觉树重新挂载、最小化和布局操作不得重新创建会话。
- MDI 子窗口与侧边工具面板停靠是两项能力。AvalonDock 是现有候选依赖，不能据其名称或已有引用认定它已满足经典 MDI。
- 实现前通过原型验证容器能力。若现有方案只满足标签和停靠，则评估独立 WPF MDI 容器配合辅助面板停靠；选型必须覆盖 MDI-03，不能悄悄缩减成标签界面。
- 浮动到主窗口之外、自由 Docking 与标签模式作为后续增强；主窗口内部的多文档操作优先交付。

## 14. 整体分阶段交付

| 阶段 | 交付范围 |
| --- | --- |
| Phase 1：会话闭环 | 按工作台区域搭建外壳，将单会话调试视图作为一个文档承载；不宣称多文档完成。见本文第 1～9 节。 |

| 布局持久化 | 验收 MDI-07；进一步安排外部浮动、Docking 和标签模式。 |

MDI 新增工作独立估算；原 Phase 1 工期不代表整个工作台的交付工期。产品完成需同时具备 MDI 工作台和完整终端能力。
