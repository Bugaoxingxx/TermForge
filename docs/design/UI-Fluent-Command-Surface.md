# TermForge — 菜单栏与工具栏命令面合并方案

> 日期：2026-09-08  
> 状态：待实施（不改 ViewModel 命令，只改 XAML 入口与 UI 测试定位）  
> 背景审阅：[2026-09-08-b3fbc1c.md](../review/2026-09-08-b3fbc1c.md)  
> 外壳方向：[UI-Win11-Fluent-Migration.md](./UI-Win11-Fluent-Migration.md)

## 1. 问题

当前命令面是「完整菜单 + 完整工具栏」：同一动作出现两次，工具栏把 MDI 四种排列做成四个并列按钮，占用过宽。这与 Win11 Fluent「高频入口精简」不一致。旧 Aero 规范也曾要求：工具栏只保留高频，排列变体收到一个可访问入口后面。

`MainWindow.xaml` 工具栏标题注释还写了两遍（约 132–137 行），整理时一并删除。

## 2. 现状对照

| 命令 | 菜单 | 工具栏 | 说明 |
| --- | --- | --- | --- |
| 新建默认终端 | 文件 → 新建终端 | 新建终端 | 完全重复 |
| 按 Profile 新建 | 文件 → 新建指定 Shell | — | 菜单独有，应保留 |
| 关闭文档 | 文件 → 关闭当前文档 | — | 菜单独有 |
| 退出 | 文件 → 退出 | — | 菜单独有 |
| 停止会话 | — | 停止会话 | 工具栏独有，应补进菜单 |
| 导航 / 属性 / 日志显隐 | 视图（勾选） | — | 菜单独有，应保留 |
| 诊断模式 | 视图（勾选） | 诊断模式 | 重复；菜单勾选语义更好 |
| 层叠 / 水平平铺 / 垂直平铺 / 全部还原 | 窗口（四项并列） | 四个按钮 | 最大重复 |
| 打开的文档列表 | 窗口 | — | 菜单独有，应保留 |
| 清空输出 | — | 清空输出 | 工具栏独有，应补进菜单 |
| 关于 | 帮助 | — | 保留 |

菜单内部近重复：**文件 → 新建终端** 与 **文件 → 新建指定 Shell** 都是「新建会话」。

## 3. 原则

- **菜单** = 完整命令面：快捷键、勾选、键盘可达；不因精简工具栏而丢命令。
- **工具栏** = 高频即时操作：图标 + 短标签；排列变体收进一个入口。
- **不改** `MainWindowViewModel` / 文档命令实现，只改入口绑定。

## 4. 目标信息架构

### 4.1 菜单

- **文件**：新建（子菜单：默认终端 `Ctrl+N` + 各 Profile）、停止会话、关闭当前文档 `Ctrl+F4`、退出 `Alt+F4`
- **视图**：左侧导航树、右侧属性面板、底部诊断日志（勾选）；分隔；原始输出诊断模式（勾选）；清空输出
- **窗口**：**排列**子菜单（层叠 / 水平平铺 / 垂直平铺 / 全部还原）；打开的文档列表（动态）
- **帮助**：关于 TermForge

### 4.2 工具栏

顺序：`新建` | `停止` | **`排列` SplitButton / MenuButton**（默认执行层叠，下拉另外三种）| `清空输出` | `诊断模式`

- 去掉四个并列的层叠 / 平铺 / 还原按钮。
- 诊断模式保留为工具栏开关，与视图菜单勾选绑定同一 `ActiveDocument.IsDiagnosticMode`。

### 4.3 AutomationId（建议）

| 入口 | Id |
| --- | --- |
| 工具栏排列主按钮 | `Toolbar.BtnArrange` |
| 下拉：层叠 / 水平 / 垂直 / 还原 | `Toolbar.Arrange.Cascade` 等 |
| 菜单排列子项 | 保留现有 `Menu.Window.Cascade` 等，或收到 `Menu.Window.Arrange.*` |
| 文件 → 新建子菜单 | `Menu.File.New`；默认项仍可用 `Menu.File.NewTerminal` |

FlaUI 现状依赖 `Toolbar.BtnCascade` / `TileHorizontal` / `TileVertical` / `RestoreAll`。合并后测试改为点 SplitButton 子项，或改走 `Menu.Window.*`。

## 5. 实施清单

1. 合并文件菜单「新建」子菜单；把停止会话、清空输出补进菜单。
2. 窗口菜单四排列收入「排列」子菜单。
3. 工具栏改为五入口 + 一个排列 SplitButton；删除重复注释。
4. 更新 `MainWindowPage` 与 `MainWindowChromeTests` / 布局类 UI 测试。
5. 核对：无文档时停止/清空/诊断禁用；Profile 子菜单仍能新建指定 Shell。

## 6. 非目标

- 不引入 Ribbon，不把菜单栏去掉。
- 不改 MDI 层叠/平铺算法。
- 不在本方案里处理强调色接线或标题栏（见 b3fbc1c 审阅）。
