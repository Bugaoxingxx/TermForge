## 发现

### [P1] `GetAccentColor()` 没有接到主题画刷

- 位置：`WindowBackdropHelper.GetAccentColor()`；`Themes/Colors.xaml`、`DarkColors.xaml` 的 `FluentAccentBrush` / `AeroFocusBorderBrush`
- 问题：API 会查 DWM / 注册表，但画刷仍是写死色。`WndProc` 收到 `WM_DWMCOLORIZATIONCOLORCHANGED` 只更新沉浸式暗色，不换 accent。提交说明写了查询强调色，UI 实际不跟随任务栏。
- 建议：在 `ApplyTheme()` 里用 `GetAccentColor()` 覆盖这两个键。`DwmGetColorizationColor` 是 Win7 玻璃着色，常与 Win11 设置里的 accent 不一致；优先注册表 `AccentColor` 或 `UISettings`，DWM 作回退。

### [P3] 版本检测测试是恒真断言

- 位置：`tests/AgentTerminal.Tests/Infrastructure/WindowBackdropHelperTests.cs`
- 问题：`Assert.True(result || !result)` 永远为真，只能证明没抛异常。`IsDarkModePreferred` 同样。
- 建议：删除恒真断言；保留 22H2 ⇒ Win11 的蕴含，以及深浅回退画刷对比。

### [P3] 去掉自绘栏后的残留

- `MainWindowChrome.xaml` 仍声明未使用的 `xmlns:shell`。
- `App.xaml.cs` 的 `using System.Windows.Media` 未使用。
- `Controls.xaml` 的 `AeroCaptionButtonStyle` / `AeroCloseButtonStyle` 主窗口已不用，仅冒烟测试仍引用。
- `ApplyHighContrastThemeIfNeeded()` 只转发 `ApplyTheme()`，可删。
- `MARGINS` 不必 `public`；`DWMSBT_NONE` / `TRANSIENTWINDOW` 未使用。

### [P3] 自定义 `Window.Template` 可以再收

- 位置：`Themes/MainWindowChrome.xaml`
- 问题：模板只剩 `Border` + `AdornerDecorator` + `ContentPresenter`，接近默认客户区。`WindowStyle=SingleBorderWindow` 且无 `WindowChrome` 时，标题栏在非客户区，这套模板一般不会吃掉系统 caption。
- 建议：若无额外客户区样式，去掉整个 `Template`，只留 `WindowStyle` / `Background`，减少与 Fluent 默认模板冲突。

## 菜单栏 / 工具栏重复

命令面重复的完整合并方案已独立成文：[UI-Fluent-Command-Surface.md](../design/UI-Fluent-Command-Surface.md)。下文只保留对照摘要。

当前命令面是「完整菜单 + 完整工具栏」，同一动作出现两次，且工具栏把 MDI 四种排列做成四个并列按钮，占用过宽、和 Win11 Fluent「高频入口精简」不一致。旧 Aero 规范也曾要求：工具栏只保留高频，排列变体收到一个可访问入口后面。

### 现状对照

| 命令 | 菜单 | 工具栏 | 说明 |
| --- | --- | --- | --- |
| 新建默认终端 | 文件 → 新建终端 | 新建终端 | 完全重复 |
| 按 Profile 新建 | 文件 → 新建指定 Shell | — | 菜单独有，应保留 |
| 关闭文档 | 文件 → 关闭当前文档 | — | 菜单独有 |
| 退出 | 文件 → 退出 | — | 菜单独有 |
| 停止会话 | — | 停止会话 | 工具栏独有，建议补进文件或会话菜单 |
| 导航/属性/日志显隐 | 视图（勾选） | — | 菜单独有，应保留 |
| 诊断模式 | 视图（勾选） | 诊断模式 | 重复；菜单勾选语义更好 |
| 层叠 / 水平平铺 / 垂直平铺 / 全部还原 | 窗口（四项并列） | 四个按钮 | 最大重复 |
| 打开的文档列表 | 窗口 | — | 菜单独有，应保留 |
| 清空输出 | — | 清空输出 | 工具栏独有，可放视图或文档菜单 |
| 关于 | 帮助 | — | 保留 |

菜单内部还有一处近重复：**文件 → 新建终端** 与 **文件 → 新建指定 Shell** 都是「新建会话」。

### 建议信息架构（不改命令实现，只改入口）

**菜单（完整命令面，保留快捷键与勾选）：**

- **文件**：新建（子菜单：默认终端 + 各 Profile）、停止会话、关闭当前文档、退出
- **视图**：左侧导航、右侧属性、底部诊断（勾选）；分隔；诊断模式（勾选）；清空输出
- **窗口**：**排列**子菜单（层叠 / 水平平铺 / 垂直平铺 / 全部还原）；打开的文档列表
- **帮助**：关于

**工具栏（高频、变窄）：**

- `新建` | `停止` | **`排列` 一个 SplitButton / MenuButton**（默认层叠，下拉另外三种）| `清空输出` | `诊断模式`
- 去掉四个并列的层叠/平铺/还原按钮。
- 诊断模式保留为工具栏开关，与视图菜单勾选绑定同一 `IsDiagnosticMode`（现状已如此）。

这样菜单不再和工具栏各摆一套四排列；「新建」在文件里合成一个子菜单；停止/清空从「只在工具栏」补进菜单，键盘用户不丢命令。

### 落地时注意

- FlaUI 现依赖 `Toolbar.BtnCascade` / `TileHorizontal` / `TileVertical` / `RestoreAll`。合并后 AutomationId 建议：`Toolbar.BtnArrange` + `Toolbar.Arrange.Cascade` 等子项；测试改为点 SplitButton 或继续走菜单 `Menu.Window.*`。
- `MainWindow.xaml` 工具栏注释写了两遍（约 132–137 行），整理时顺手删一处。
- 不改 ViewModel 命令，只改 XAML 入口与测试定位。
