## 并发正确性核验

- **锁序一致**：全仓仅 `_bufferLock → Buffer.SyncRoot` 一种嵌套（`FlushPendingBufferLocked`、`ClearOutput`）；`OnRender` / `OnResizeDebounceTick` / `ResizeAsync` 只取 `SyncRoot`，无反向获取，不会死锁。
- **线程亲和性**：`AppendOutput` 中后台线程经 `Dispatcher.BeginInvoke` 再 `_flushTimer.Start()`，UI 线程直接 `Start()`，不会跨线程操作 `DispatcherTimer`。
- **单线程 buffer**：`Parse` 仅在 flush tick（UI 线程）执行；`RequestRefresh → InvalidateVisual` 仅标脏，不触发同步重入渲染，`_bufferLock` 内调用安全。
- **无遗漏写路径**：buffer 写入仅 `Parse`/`Resize`/`Clear`，均已加锁；键盘输入走 `Session.WriteAsync`，不直接写 buffer。

## 发现（均为 🟢 nit，不阻塞）

1. `TerminalControl.cs:434` 滚轮处理读 `Buffer.ScrollbackLineCount` 未进 `SyncRoot`；int 读原子，最坏为钳制值短暂过期，不崩。追求完全一致可纳入锁。
2. `TerminalBuffer.InsertLines/DeleteLines` 未把 `count` 限制到滚动区高度；参数上限 10 万时会做约 `count×rows` 次行指针搬移。建议 `count = Math.Min(count, scrollBottom - y + 1)`。
3. `FlushGlyphRun` 仍 `.ToArray()` 两个数组/run/帧——每行 List 分配已消除，但受 `GlyphRun` API 限制无法完全零分配，可接受。
4. `DECSC/DECRC`（`ESC 7/8`）仅存取光标位置，未保存 SGR 属性/字符集（完整 DECSC 应含）。低风险，建议记入已知限制。
5. brush 缓存达 1024 时整表 `Clear()` 而非 LRU；同帧 >1024 种色才可能抖动，罕见，可接受。
6. AC07 测试对 `doc.DisposeAsync()` 调用两次（try 内 + finally）。若 `DisposeAsync` 非幂等，finally 第二次可能抛异常并掩盖断言失败。建议确认幂等或仅保留 finally 释放。
