## 发现（UI）

### [P0] 三个面板 `Border → ContentControl`，背景与边框将不再渲染

- 位置：`src/AgentTerminal.App/MainWindow.xaml`（导航面板 `Pane.Navigation`、诊断面板 `Pane.Diagnostics`、属性面板 `Pane.Properties`）
- 问题：容器由 `<Border Background/BorderBrush/BorderThickness>` 改为 `<ContentControl Background/BorderBrush/BorderThickness>`。`ContentControl` 默认控件模板仅含 `ContentPresenter`，**不绘制** `Background`/`BorderBrush`/`BorderThickness`。全量检索确认工程中**无任何 `ContentControl` 隐式样式或模板**（`Controls.xaml`/`MainWindowChrome.xaml`/`AeroDockingTheme.xaml` 均无，`PresentationFramework.Aero` 也不会给无外观的 `ContentControl` 加背景）。
- 影响：
  - 导航面板底色 `#F8FAFD`、属性面板底色 `AeroPropertiesBackgroundBrush`(#F5F8FC) 丢失。因内部 `TreeView`/`ScrollViewer` 透明，会透出主窗口客户区玻璃底色 `AeroGlassBrush`，与设计不符。
  - 三个面板与相邻区之间的 1px 分隔边框（`0,0,1,0` / `1,0,0,0` / `0,1,0,0`）全部消失，面板间失去视觉分界。
- 根因：改 `ContentControl` 的动机应为在 UIA 树暴露 `AutomationProperties.Name`，但代价是丢失 `Border` 的绘制能力。
- 建议（二选一）：
  - 方案 A（推荐，最小改动）：改回 `Border`，`AutomationProperties.AutomationId/Name` 附加属性在 `Border` 上同样可设。
  - 方案 B：保留 `ContentControl` 承担 automation 语义，但内部用 `Border` 负责绘制背景与边框。
- 备注：commit message 称「18 项 UI 自动化测试通过」，但这些测试仅校验 `AutomationId` 与交互，不做像素级背景比对，无法捕获此回归。需运行截图核对。

### [P1] 同一逻辑区域出现重复 `AutomationId`

- 位置：`src/AgentTerminal.App/MainWindow.xaml`
- 问题：改造后容器与其内部子控件被赋予相同 `AutomationId`——导航（`ContentControl` 与 `TreeView` 均为 `Pane.Navigation`）、诊断（`ContentControl` 与 `TextBox` 均为 `Pane.Diagnostics`）、属性（`ContentControl` 与 `ScrollViewer` 均为 `Pane.Properties`）。
- 影响：同一 UIA 树内重复 `AutomationId` 使 `FindFirst` 定位产生歧义。
- 建议：保证可见树内 `AutomationId` 唯一，如容器 `Pane.Navigation`、内部树 `Pane.Navigation.Tree`。

### [P1] 自绘 Chrome 最大化时可能顶部被裁

- 位置：`src/AgentTerminal.App/Themes/MainWindowChrome.xaml`（`WindowState=Maximized` 触发器）
- 问题：`AllowsTransparency=False` 的 `WindowChrome` 自绘窗口最大化时会外扩边框量，导致顶部 30px 标题栏被工作区裁切；当前仅把 `WindowRootBorder.BorderThickness` 置 0，未见对最大化的 `Margin`/`Padding` 补偿。
- 建议：在 Maximized 状态给根容器加边距补偿（常见 `Margin="8"` 或按 `SystemParameters` 计算），并在目标机验证最大化后控制按钮完整可见。

### [P3] 高对比度下「成功/危险」语义色无法区分

- 位置：`src/AgentTerminal.App/Themes/HighContrast.xaml`
- 问题：`AeroTextSuccessBrush` 与 `AeroTextDangerBrush` 均映射到 `SystemColors.HighlightColor`，高对比度用户无法从颜色区分「运行中」与错误/停止。
- 建议：`Danger` 改用 `HotTrackColor`，或结合图标/文字等非颜色提示。

## 发现（逻辑代码，随附）

### [P1] 删除 `OutputText` 跨线程封送，与后台线程调用链冲突

- 位置：`src/AgentTerminal.Docking/ViewModels/TerminalDocumentViewModel.cs`（`FlushPendingBufferLocked`）
- 问题：移除了 `OutputText` 赋值的 `Dispatcher.BeginInvoke` 封送。而 `OnSessionProcessExited`（`ITerminalSession.ProcessExited` 处理器）在 `ConPtyTerminalSession` 的 `Task.Run(WaitForProcessExitAsync)` **后台线程**触发，其 `FlushOutput → FlushPendingBufferLocked → OutputText=` 会在后台线程执行。
- 影响：现依赖 WPF 绑定引擎对单值绑定的自动封送（与 `State`/`StatusMessage` 一致），实践中通常可行，但若 `OutputText` 绑定为 `TwoWay`/带 `Converter`/目标控件在 `PropertyChanged` 同步访问 UI 元素，会抛跨线程异常。移除了一层显式防御。
- 建议：恢复封送，或在 `FlushOutput`/`OnSessionProcessExited` 处显式调度到 UI 线程。

### [P1] 构造函数 `_flushTimer` 收窄条件形成隐式「必须 UI 线程构造」契约

- 位置：`TerminalDocumentViewModel` 构造函数（新增 `Dispatcher.CheckAccess()` 等判断）
- 问题：若 VM 不在 UI 线程构造，`_flushTimer` 恒为 null，输出全部退化为同步刷新，与上一条叠加放大后台线程赋值 `OutputText` 的风险。当前生产在 UI 线程同步构造（`MainWindowViewModel.CreateNewDocument`）契约成立，但无注释/断言保护。
- 建议：补充说明性注释或断言，或让 timer 绑定到当前应用 Dispatcher 而非依赖构造线程。
- 备注：新增的 `Dispatcher.Thread.IsAlive` / `HasShutdownStarted` 关停期防御是好的改进。

### [P3] `ActivateDocument` 存在一层重入

- 位置：`src/AgentTerminal.App/ViewModels/MainWindowViewModel.cs`
- 问题：`foreach` 内设置 `d.IsActive=true` 时 `ActiveDocument` 尚未更新，触发 `PropertyChanged` 回调重入一次 `ActivateDocument`。递归深度为 1、最终状态一致、不改集合结构（不抛异常）。
- 建议：先设 `ActiveDocument = doc` 再遍历，消除重入。

### [P3] `PropertyChanged` 匿名订阅未随文档关闭取消

- 位置：`MainWindowViewModel.CreateNewDocument`
- 问题：`RequestClose` 与 `PropertyChanged` 均为匿名 lambda，关闭时未 `-=`。因委托由 `doc` 持有、`doc` 移除后可回收，不致 `MainWindowViewModel` 泄漏，影响很小。
- 建议：留意即可，或在关闭时解绑。

### [P3] 其它

- `MainWindow.xaml.cs` 系统菜单弹出位置使用魔法数字 `PointToScreen(new Point(0, 30))`，在不同 DPI/主题下会偏移，建议以标题栏实际高度计算。
- `App.OnUserPreferenceChanged` 使用同步 `Dispatcher.Invoke`，建议改 `BeginInvoke` 避免潜在阻塞。
- `MdiChildWindowAutomationPeer.SelectionContainer => null`，`ISelectionItemProvider` 规范上应返回选择容器。

- 矢量 `Geometry`/`Path`（`MdiMinimizeGeometry` 等）替换 `□`/`❐`/`✕`/emoji，消除跨字体字形漂移，MDI 与主窗口共享同一套几何定义。
