## 发现

### 🟡 [important] 工具栏排列下拉的 `ContextMenu` 很可能丢 `DataContext`

- 位置：`src/AgentTerminal.App/MainWindow.xaml`（`Toolbar.BtnArrangeDropdown` 的 `Button.ContextMenu`）；`MainWindow.xaml.cs` `OnArrangeDropdownClick`
- 问题：`ContextMenu` 不在可视化树里，默认不继承窗口 `DataContext`。四个 `MenuItem` 写的是 `Command="{Binding CascadeCommand}"` 这类绑定，若 `DataContext` 为 null，下拉项能显示、UIA 也能 `Invoke`，但命令不会执行。`OnArrangeDropdownClick` 只设了 `PlacementTarget` / `Placement` / `IsOpen`，没有把 `DataContext` 带过去。
- 测试掩盖：`ClickTileHorizontal` 等在找到 `Toolbar.Arrange.*` 后立刻 `return`，**不会**走到窗口菜单回退。`UiaWait.Until` 超时会抛异常而不是返回 null，下拉按钮存在时菜单回退基本是死代码。
- 建议：给 `ContextMenu` 显式接上放置目标的 VM，例如：

```xml
<ContextMenu DataContext="{Binding PlacementTarget.DataContext, RelativeSource={RelativeSource Self}}"
             AutomationProperties.AutomationId="Toolbar.Arrange.Menu">
```

或改用真正的 `Menu`/`Popup`，避免把 SplitButton 做成「右键菜单左键弹出」。合入前用一次：点下拉 → 水平平铺，确认子窗口真的变布局，不要只看菜单是否出现。

### 🟡 [important] 高对比度提前 `return` 不会清掉根级强调色覆盖

- 位置：`src/AgentTerminal.App/App.xaml.cs` `ApplyTheme()`
- 问题：非 HC 时 `Resources["FluentAccentBrush"] = accentBrush` 写在 **Application 根字典**，查找优先级高于 `MergedDictionaries`。切到高对比度时只合并 `HighContrast.xaml` 然后 `return`，根上两个键还在，会盖住字典里的 `SystemColors.HighlightColor`。进程从普通主题再开 HC（正是 `UserPreferenceChanged` / `WM_SETTINGCHANGE` 要处理的路径）时，焦点边框和强调色不再跟系统高对比度走。
- 建议：HC 分支在 `return` 前 `Resources.Remove("FluentAccentBrush")` 和 `Resources.Remove("AeroFocusBorderBrush")`；或把覆盖放到独立 `ResourceDictionary`，切 HC 时整本撤掉。

### 🟡 [important] 「新建」比方案多一层

- 位置：`MainWindow.xaml` 文件菜单；对照方案 §4.1
- 问题：方案是「新建（子菜单：默认终端 + 各 Profile）」。实现是 文件 → 新建 → **再建「新建指定 Shell」** → Profile。按 Profile 新建多一次点击，也和「合并两个新建入口」的动机不完全一致。
- 建议：`AvailableProfiles` 直接挂在「新建」下、跟「默认终端」同级；保留 `Menu.File.NewProfileTerminal` 也可以，但不必再套一层 Header。

## 次要

🟢 **[nit]** `FluentAccentBrush` 与 `AeroFocusBorderBrush` 共用同一 Frozen 实例。现在没问题；以后若焦点色要单独调，会一起变。

🟢 **[nit]** 设计文档仍写「状态：待实施」。本提交已经落地，建议改成「已实施」并链到本审阅。

🟢 **[nit]** `GetAccentColor()` 用 `is int` 接注册表 DWORD。alpha 高位时仍是负数 `int`，位运算没问题；若将来有环境给出 `uint`，会静默落到 DWM 回退。

💡 **[suggestion]** 深色字典里的 `#60CDFF` 是为暗背景准备的浅强调色。`ApplyTheme` 用注册表原色覆盖后，深色模式下焦点边框可能偏暗。Win11 深色常用 Accent 的浅变体；可按 `IsDarkModePreferred()` 提亮，或至少在深色下抽一次对比度。

💡 **[suggestion]** 工具栏「排列」是两个 `Button` + `ContextMenu`，不是 Fluent `SplitButton`。可接受（方案写了 SplitButton / MenuButton）；键盘会变成两个 Tab 停靠点。若后续要无障碍更好，可合成一个带 `ExpandCollapse` 的控件。

💡 **[suggestion]** 没有测试断言 `ApplyTheme()` 真的改写了两个画刷；`GetAccentColor_ShouldReturnValidOpaqueRgbColor` 只证明 A=255。可加一个 STA 小测试：调用 `ApplyTheme()` 后根资源类型/颜色与 `GetAccentColor()` 一致。

📚 **[learning]** WPF 里 `ContextMenu` / `Popup` 的 `{Binding}` 不走窗口可视化树。菜单栏里的 `MenuItem` 还在逻辑树里，所以窗口「排列」子菜单的 `Command="{Binding CascadeCommand}"` 通常没问题；工具栏这套下拉是另一类。FlaUI 能点到菜单项 ≠ 命令已执行。
