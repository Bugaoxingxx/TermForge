## 发现

### [P2] 右下钳制断言无法证明钳制发生了

- 位置：`tests/AgentTerminal.UITests/Specs/MdiWorkbenchLayoutTests.cs:209-224`
- 问题：`+3000,+3000` 拖动后的断言为 `Left <= workspace.Right - 50`、`Top <= workspace.Bottom - 30`，以及 `Right > workspace.Left + 50`、`Bottom > workspace.Top + 30`。产品规则是将 `Left`/`Top` 钳到 `canvas.Width - 60` / `canvas.Height - 40`。后两条检查的是窗口右/下边是否仍在工作区左/上侧之外，方向与右下钳制相反。前一次 `-800,-800` 成功后窗口已在工作区左上角；若第二次拖动完全未生效，四条断言仍然通过。注释写保留 60×40 可见区域，代码却使用 50/30，且未计算窗口与工作区的交集。
- 影响：右下边界钳制失效、或第二次拖动成为空操作时，测试仍会通过，无法保护本次新增场景。
- 建议：保存第一次钳制后的矩形，断言第二次拖动后 `Left`/`Top` 明显增大，并接近 Canvas 右/下内侧约 60/40 像素（可留 DPI 容差）。按产品规则用交集验证至少保留的可见区域。

### [P2] 工作区矩形用了整个 `MdiContainer`，含底部最小化托盘

- 位置：`tests/AgentTerminal.UITests/Specs/MdiWorkbenchLayoutTests.cs:192`
  对照：`src/AgentTerminal.Docking/Controls/MdiContainer.xaml`（Grid 第 0 行为 Canvas，第 1 行为 `MinimizedTray`）、`src/AgentTerminal.Docking/Controls/MdiChildWindow.xaml.cs:135-140`
- 问题：`workspace.Container` 是 `Workbench.MdiContainer`。产品钳制使用 `FindParentCanvas().ActualWidth/Height`，不含托盘。测试却用整个容器的 `BoundingRectangle`，其 `Bottom` 比 Canvas 底边更靠下。
- 影响：窗口即使被拖进托盘区域，`Top <= container.Bottom - 30` 仍可能通过。左/上边界碰巧接近，底边断言偏松，无法按产品规则验证下边界。
- 建议：使用 Canvas（或 ItemsControl 工作区）的屏幕矩形作为钳制参照，不要使用带托盘的整个 `MdiContainer`。

### [P2] 物理路径的「成功」只验证了光标，未验证手势

- 位置：`tests/AgentTerminal.UITests/Infrastructure/InputSimulator.cs:55-68`、`108-117`
- 问题：`Mouse.Position = startScreen` 之后立刻回读光标，偏差 ≤ 5px 即执行物理拖动/双击并 `return`。FlaUI 的 `Position` setter 内部已经 `SetCursorPos` 并回读，再读一次几乎总会落在 5px 内，因此总会走物理路径。`Down`/`MoveTo`/`Up` 若不抛异常（`SendInput` 返回成功但系统未真正注入），不会回退到 Win32。`DoubleClick` 同样只检查光标。对照上次审阅建议：物理输入成功后返回；若处理 `SendInput` 静默失效，应先确认窗口位置或状态已变，再决定是否回退。当前实现只做了前半句。此外，`MdiChildWindowPage.DragBy` / `DoubleClickTitleBar` 在 `ITransformProvider` / `IWindowProvider` 可用时不会进入 `InputSimulator`，本修复对现有 MDI UI 测试几乎走不到。
- 影响：物理点击/拖动静默失败时不再走 Win32 回退，相关测试可能不稳定；现有 MDI 布局测试实际走的是 `Transform.Move` / `SetVisualState`，该修复对其双重注入问题没有覆盖。
- 建议：在物理路径 `return` 前确认目标元素位置或窗口状态已变化；未变化再执行 Win32 回退。不要用 `SetCursorPos` 回读作为成功条件。

### [P3] AC03 仍用固定 Sleep，且比 AC01 更短

- 位置：`tests/AgentTerminal.Tests/ConPty/PowerShellSessionIntegrationTests.cs:191-192`
- 问题：`AC01` 为避开 PSReadLine 清空缓冲等待 1500ms；`AC03` 本次加入 1200ms。慢机器或冷启动下，`Start-Sleep` / `Ctrl+C` 仍可能打在提示符就绪之前。固定延时只能降低 flake，不能消除竞态。
- 影响：`AC03_Interrupt_ShouldCancelLongCommandAndAllowNextCommand` 在并发或慢环境中仍可能失败。
- 建议：等待输出中出现提示符后再发送长命令；至少与 `AC01` 使用相同的 1500ms。
